# Simple Architecture

В проекте используется Simple Architecture — подход, объединяющий Clean Architecture и VIPER из iOS-разработки, преимущественно VIPER. При разработке ориентируйся на описанные ниже правила проекта.

## Структура

- `app` — инициализация приложения и точка входа.
- `pages` — страницы приложения. Компонент, который используется только на одной странице, размещай в `pages/some-page/components`.
- `components` — компоненты, переиспользуемые между страницами. Например, разметку найденных фильмов, общую для `home` и `user/favorites`, размещай в `src/components`.
- `ui-kit` — чистый UI: JSX-разметка и CSS. Хуки, провайдеры и другие средства допустимы только для управления представлением: например, `useState` для `isOpened` или собственный Context сложного составного компонента.

Компоненты как в `src/components`, так и в `pages/some-page/components` могут содержать собственные вложенные `components`.

## Логика компонентов

В `pages` и `components` всю логику компонента, включая создание функций, помещай в хук `usePresenter`. Например, `src/components/Card` содержит `Card.tsx`, `Card.module.css` и `usePresenter`:

```tsx
function Card(props: CardProps) {
  const presenter = usePresenter(props);

  return <div>{/* представление */}</div>;
}
```

`usePresenter` может использовать любое количество хуков. Его интерфейс и аргументы проектируются для нужд самого presenter, а не компонента: компонент зависит от `usePresenter`, а не наоборот.

`usePresenter` обычно принимает props компонента целиком. Если у компонента нет props или presenter не зависит от входных данных, хук вызывается без аргументов.

В `ui-kit` не используй `usePresenter`: компонент управляет только представлением через React-хуки и обработчики. Стили — нативный CSS с CSS Modules.

Логику компонентов в `ui-kit` и `components` дроби на хуки по смыслу: каждый хук отвечает за отдельную задачу или поведение. То же правило действует внутри `usePresenter`: он объединяет специализированные хуки, а не собирает всю логику в одном месте. Хуки конкретного компонента выноси в его поддиректорию `hooks`, например `components/Card/hooks/useCardFocus.ts`. Это относится и к `usePresenter`: размещай его в `hooks/usePresenter.ts` (или `.tsx`, если нужен JSX).

## Утилитарные функции

Любая утилитарная функция должна быть вынесена из файла, в котором она используется, в отдельный файл в корень директории. Одна функция — один файл. Файл называется так же, как функция, и экспортирует только эту функцию.

Например, хелпер `formatTitle`, используемый в `components/Card/Card.tsx`, размещается в `components/Card/formatTitle.ts`, а не внутри `Card.tsx` и не в `components/Card/utils/formatTitle.ts`.

Это правило действует для всех директорий проекта: `app`, `pages`, `components`, `ui-kit` и их вложенных поддиректорий.

## Типы

Все публичные типы компонента — props, options, state и другие определения, которые экспортируются за пределы файла, — выноси в `types.ts` в директории этого компонента. Например, `components/Card/types.ts` содержит `CardProps`, а `components/Card/Card.tsx` импортирует его оттуда.

Файл компонента может реэкспортировать тип из `types.ts`, если нужно сохранить работоспособность глубоких импортов вида `@ui-kit/card/Card`. Каноническое место определения типа — `types.ts` в директории компонента.

Файлы `index.ts` и `index.tsx` разрешены в `app` — в точке входа приложения — и в публичных баррелях на границах модулей, например `ui-kit/index.ts` для реэкспорта компонентов набора. В остальных местах используй именованные файлы.
